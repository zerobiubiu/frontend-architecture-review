## SDK 做了什么，业务仍必须做什么

当前固定依赖 `@binance/stocks 1.0.6`、`@binance/common 2.5.2`、`@binance/wallet 22.2.7`。已核对Common 2.5.2官方npm发布包摘要与锁文件一致，安装的 `dist/index.mjs` 与该发布包字节一致；未修改 `node_modules`。实现按实际HTTP错误映射设计，不假定SDK会处理本系统账本、任务或客户订单幂等。

|实际响应／失败|SDK 实际结果|本系统后果|
|---|---|---|
|HTTP 2xx|`data()` 只解析 JSON，不自动拒绝 `{code,msg}`|统一 `sdkData` 拦截错误包络；下单仍未知，**即使 code 是拒单白名单也不把 2xx 包络当作无单证明**|
|HTTP 400|`BadRequestError` 保留数字 `code`|只有 SUBMIT＋显式可证明拒单白名单形成 `ExchangeSubmissionRejected`；不检查原始 msg 关键词|
|HTTP 401／403|`UnauthorizedError`／`ForbiddenError` 保留 code|提示凭据、IP 或资格权限；不伪造 HTTP400 拒单证据|
|HTTP 404|`NotFoundError` 保留 code|查询未确认，查无不等于不存在，不释放未知占用|
|HTTP 418／429|`RateLimitBanError`／`TooManyRequestsError` 保留 code，不保留响应头|传输层在 SDK 映射前持久化 Retry-After 与封禁冷却；应用门禁复用该期限|
|HTTP 5xx|`ServerError` 只保留 HTTP statusCode，原包络 code 被 SDK 丢弃|服务故障、写入未知；不能把 HTTP statusCode 当作业务码。若原包络为限流，传输层仍先保存共享冷却|
|其他 HTTP 错误|`ConnectorClientError` 保留数字 code|安全映射、写入未知，不推定确定拒单|
|网络／超时|`NetworkError.transportCode` 与数字业务码不同|仅白名单传输代码可用于安全分类；未到达／已到达不能凭网络异常猜测，写入保持未知|

所有请求继续 `retries: 0`，共享 Axios 继续 `maxRedirects = 0`，不自行签名、不加入 API 模拟回退、不安装新依赖。日志、返回体与审计只使用本地安全中文语义、受验证数字 code、HTTP 类别及白名单 transportCode；**不回显上游 msg、完整配置、API Secret、Listen Key 或签名**。未知新增码仍显示安全可追踪的数字 code，不因为不在“未知列表”中就推定拒单。

读取暂态故障继续使用应用层既有等待码：系统繁忙／行情暂不可用与未知新增码为 `EXCHANGE_UNAVAILABLE`，网络仍为 `EXCHANGE_NETWORK_UNCERTAIN`，限流仍为 `EXCHANGE_RATE_LIMIT`；数字业务码另存 `exchangeCode` 和安全消息供诊断。这样不会把可等待下一周期的读取失败误改为永久 `PREFLIGHT_FAILED`。已具名的参数、权限与明确规则失败仍要求修正，不以无限自动提交“恢复”。

## 按操作执行的确定性规则

|操作|允许的恢复|禁止的推断／副作用|
|---|---|---|
|READ|服务／参数／权限恢复后安全再次读取；收到错误不提供假资产、零余额或替代订单|查无单、过期目录、不可验证 JSON 不能释放已经开始提交的占用|
|SUBMIT|真实 SDK HTTP400＋显式白名单才提供拒单证据；应用结算仍检查外部订单、成交与已释放状态|未知、超时、繁忙、服务故障、限流、通用 new-order 错误或重复 ID 只能核对原 clientOrderId；不换号、不自动重发|
|CANCEL|回执后仍查原订单与实际成交；撤单中继续保留剩余预留|486411/412/444/446/447、通用撤单拒绝或无订单都不是撤单成功；不逆转已记成交|
|STREAM|失效key、协议或权限错误使流失败；同步关闭旧资源，维持原30秒退避后重建，凭据修正可触发新生命周期；退避期持续降级，事件只记录一次|订阅失败不能因错误队列已消费而记健康；新key不证明成交，推送只唤醒原单只读核对，不直接结算|

- `-1000/-1006/-1007`、系统繁忙／服务故障、`-2010` 及 `486449` 都不能触发释放或重发。**486449 的官方“使用新的 clientOrderId 重试”被本系统持久化交易意图安全规则覆盖**：同一意图永远只核对原 ID。
- `-5012` 在官方同页既是 `TRANSFER_PENDING`，又是 `FUTURE_ACCT_OR_SUBRELATION_NOT_EXIST`。实现保留两个 alias 和歧义说明，**不凭码猜“处理中”或“账户不存在”，更不能按泛化“重试”文案重发**。本项目也不新增划转、合约或子账户操作。
- UI-only 的 `486217/486431/486432/486433` 已从 API 明确拒单证据中排除；这些参数场景按官方规则优先返回前置 `-1102`。意外收到 UI-only 码仍安全报错、写入未知。
- `-1003` 与资金接口频率码 `-4005` 不依赖 HTTP429 才冷却；HTTP200／400／500 的相应包络同样在映射前保存冷却。真实限流响应不是本地“未发送”证据；只有 HTTP 前共享门禁阻断且由单次请求证据记录的 `ExchangeRequestNotSent` 才能用于本地未发送判定。
- `-1125/-3038` 通过实际流失败路径处理；HTTP401/403 和凭据权限码也不会被吞成健康连接。SDK 不保留的业务码不从原始错误字符串补猜。纯 `DomainError` 保留本地 code/message 并映射 409，既有 `BusinessError` 原样保留，不误报上游不可用。
- 所有拒单证据都只描述本次 SUBMIT，不将读取、撤单、流恢复变成原订单拒单。保留现有金融事务和锁、暂停／停止不自动撤单、管理员无交易权限、SELL 来源缺口继续关闭。S/F 仍只是请求回执，绝非成交或终态证据。
