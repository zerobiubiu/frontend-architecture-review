# 当前后端可提供的前端开发信息

- 用途：提供给前端技术选型和项目规划人员的独立摘要；不指定前端框架、组件库或视觉方案。
- 基线：`dev` 分支源码 `0cda648`，后端版本 **3.0.0**；本摘要不代表新前端、当前部署或真实资金交易已经验收。
- 本分支当前只包含后端及业务资料，没有可直接使用的前端工程；桌面和移动端均需考虑。

## 1. 产品与用户

这是面向 Binance Stocks 证券的交易管理系统，包含登录后的交易员和管理员两类用户。后端按角色与数据所有者授权，客户端不能通过隐藏按钮代替服务端权限检查。

- **交易员**：管理本人的一个活动交易账户及凭据、查看资金和持仓、创建单笔订单与批量任务，查看订单、成交和执行记录。
- **管理员**：管理用户及授权、跨用户查看业务、限制账户、暂停／停止／核对任务、设置平台限制和急停。管理员不能直接买卖或撤单，也不能启动／继续任务；任务控制仍可能推进此前已授权的自动撤单。
- **后台执行**：批量任务由独立 Worker 推进；关闭页面、退出登录或浏览器断开，不等于停止任务或撤销订单。

## 2. 前端可用的后端能力

后端提供 **52 个明确的方法／路径组合**；业务路径以 `/api/v1` 开头，健康检查为 `/healthz`。下表列代表入口，不要求界面按这些路径组织页面。

|功能|可提供的数据或操作|代表入口|
|---|---|---|
|身份与安全|登录、当前身份及 CSRF、退出、本人改密|`/auth/login`、`/auth/me`、`/auth/logout`、`/auth/password`|
|账户与市场|账户配置、连接检查、资产同步和核对；官方证券目录、持仓候选与报价|`/accounts`、`/accounts/:id/check`、`/market/symbols`、`/market/holdings`、`/market/quotes`|
|单笔交易|预检、限价／市价订单、订单详情、撤单与原单核对|`/orders/preflight`、`/orders`、`/orders/:id`|
|批量任务|完整配置的创建与编辑，启动、暂停、继续、停止和核对|`/tasks`、`/tasks/:id/control`|
|业务查询|概览、本地持仓和账本、核对记录、业务事件；账户维度的官方订单／成交历史|`/overview`、`/positions`、`/ledger`、`/reconciliations`、`/logs`、`/accounts/:id/exchange/*`|
|平台管理|用户、账户限制、订单／任务监管、审计、平台设置及官方节点测速|`/admin/users`、`/admin/accounts`、`/admin/orders`、`/admin/tasks`、`/admin/audit`、`/admin/system`|
|原操作恢复|读取未解决操作、按原 UUID 查询或继续允许的核对|`/operations`、`/operations/:id`、`/operations/:id/reconcile`|
|实时通知|业务资源变化通知、指定账户／证券的行情推送|`/events`、`/market/quote-stream`|

订单、任务、账户等各自有状态、来源、时间及错误信息；有的列表是真分页，有的是全量数组。相同查询字段不一定对每种资源生效，不能假设所有列表支持相同筛选或排序。`/logs` 是授权业务事件，不是服务器运行日志下载。

## 3. 接口、实时与认证方式

- **HTTP 与数据**：默认本机访问基址为 `http://127.0.0.1:3020`，实际以部署配置为准。成功响应通常为 `{ data: ... }`，错误通常为 `{ error: ... }`；高风险操作还可能附带 `operation`。HTTP 成功、业务已应用和交易所成交是不同事实。JSON 请求体上限为 64 KiB。
- **公开类型**：后端交付 `backend/contracts/client.d.ts` 和 `backend/contracts/validation.ts`。TypeScript 调用方可用 Hono 客户端推导类型、用 Zod 复用公开校验；当前后端依赖 Hono 4.13.13、Zod 4.6.7。前端不必采用 TypeScript 或 Hono，也不能导入后端内部源码作为运行依赖；其他技术栈可按 HTTP／JSON 接入。当前源码与公开契约中未发现 OpenAPI／Swagger 描述，不能假定可以据此自动生成其他语言的客户端。
- **会话**：登录成功设置 HttpOnly Cookie，并返回用户和 CSRF。后续写请求除登录外须携带 `X-CSRF-Token`；需要可信的精确 Origin。跨源请求需携带凭据；Cookie 的 SameSite 默认 `strict`，真正跨站部署还受 HTTPS 和浏览器第三方 Cookie 策略限制。会话有效期为 8 小时。
- **实时**：业务 SSE 给出需要重新读取的资源提示，不是完整业务账本；行情 SSE 提供 `quote`／`status`。两路使用默认 `message` 数据帧，无事件补播保证，断线重连后需重新读取权威状态。两路共享每用户、每 API 进程最多 6 条连接的限制。
- **部署**：API 与 Worker 独立运行，后端不托管前端静态文件。可以由部署方安排同源代理或跨源访问，但必须满足 Cookie、Origin、CSRF 和 SSE 条件；本项目不提供反向代理或主机部署配置。

## 4. 前端必须表达的业务状态

1. **三类单笔输入互斥**：LIMIT 使用价格与股数；MARKET BUY 按本金；MARKET SELL 按股数。市价不传限价和交易时段，且仅支持 DAY。批量任务也分别使用股数或本金目标。
2. **精度与时间**：价格、股数、本金以十进制字符串传输；限价最多 2 位小数，请求股数最多 10 位小数，市价本金最多 18 位小数。任务间隔是 JSON 数字，最多 3 位小数秒。未修改的计划时间应保留原 UTC 字符串精度，不用浮点或毫秒时间转换覆盖原值。
3. **多层状态**：任务、订单及原操作回执是不同状态机。订单有 `ACCEPTED`、`PARTIALLY_FILLED`、`CANCELING`、`UNKNOWN` 等；任务有 `RUNNING`、`PAUSED`、`RECONCILING`、`RECOVERY_REQUIRED` 等；原回执另有 `PROCESSING`、`SUCCEEDED`、`REJECTED`、`UNKNOWN`、`CONFLICT`。未知、缺失和读取失败不能显示为零、成功或确定失败。
4. **数据来源**：买入预算使用官方 Funding 钱包 USDC；Spot 资产为只读展示，不并入购买力。本地名义持仓／成本、官方持仓候选和当次可卖库存不是同一数据；预检不锁定未来资金，也不保证成交。
5. **原 ID 恢复**：下单使用订单 `Idempotency-Key`；撤单、任务控制、账户检查／同步／核对及部分管理操作使用 UUID 原操作 ID。请求超时或页面关闭后，保留非敏感原身份和原 ID，先按原记录核对，不自动换 ID 重发。账户／任务保存、用户创建及改密没有统一持久原回执，不能凭当前快照伪造原请求终态。

## 5. 当前不能提供或仍待处理的能力

- 没有忘记密码／管理员重置密码、任意资源删除、独立本地全局成交分页、完整官方盈亏计算、K 线／回测、虚拟资金或运行时 Testnet／Demo。
- 原始需求要求评估买入任务的整份预计资金；当前启动流程按实际分支检查单批或资金来源，未发现完整目标资金需求的公开评估。是否需要补齐须另行确认。
- 已知旧会话的迟到 401 可能清除新 Cookie：独立浏览器模拟已观察到该机制，但尚未在项目 API／数据库或跨标签页端到端复现。不存在与越权的错误表达可能泄露对象存在性；原操作前置拒绝与正常执行的输入归一化差异可能导致同一请求出现原 ID 冲突，后者尚未全链路复现。
- 静态声明未覆盖全部运行时空值、错误分支和 SSE 载荷，例如无 Worker 时的部分心跳时间可为 `null`。此前一次 `contracts:check` 字节校验失败尚未定位；后续独立导出一致不代表该问题已修复。

## 6. 选择前端技术时需要核查什么

|选型维度|应能满足的实际需求|
|---|---|
|请求与部署|独立部署，支持携 Cookie 的 HTTP、CSRF、同源或受控跨源，以及生产代理路径前缀|
|数据与实时状态|支持两路 SSE、断线重读、资源级刷新、会话切换和多标签下的状态隔离|
|表单与数据精度|支持条件字段、严格字符串小数、复杂校验、精确 UTC 时间，以及列表筛选和分页差异|
|写操作与恢复|能保留非敏感原 ID，区分待核对、已应用但后续读取失败和明确拒绝；不能对所有写请求启用通用自动重试|
|界面与验证|支持两类角色、桌面／移动端及隔离环境下的交互和故障验收；具体目标浏览器版本、无障碍等级、视觉规范与性能指标尚待确定|

开发或验收不能默认存在真实交易测试网：产品运行连接 Stocks 正式环境；应使用临时数据库和隔离网关等测试手段，真实买卖、撤单须另行明确授权，系统不代签风险声明。
