- 状态：现状参考；持续维护，不是历史执行报告。
- 基线：后端 **3.0.0**／`dev`源码 **596849a**；本文档补全不改变程序行为或版本。
- 目标：通过本目录、[产品功能](../../PRODUCT.md)与[公开契约](../../backend/contracts/)理解后端并实现覆盖现有能力的客户端；旧工程、页面和设计稿不是接入前置。
- 边界：不预设应用框架、组件库、路由布局或视觉方案；资料覆盖不等于后端安全问题已修复，也不等于新客户端、部署或实盘已验收。

## 2. 事实源与静态类型的使用边界

|事实|权威材料与解释|
|---|---|
|本项目当前业务范围|`PRODUCT.md`；本目录解释其实际接口、角色和执行规则，不从旧应用推断附加功能|
|HTTP路径、请求／成功响应字段|`backend/contracts/client.d.ts`的`ApiClient`；逐方法路径与用途按接口目录定位|
|输入规则、状态枚举与载荷schema|`backend/contracts/validation.ts`；在独立项目显式同步，不导入`backend/src/`|
|普通错误、请求头、Cookie、SSE传输、已知运行空值|本目录对应专题；生成类型不穷尽中间件或流生命周期，不允许用类型断言抹去这些规则|
|历史验收、失败、部署与实盘证据|对应变更／验证记录只证明各原轮；当前3.0.0尚未部署，不能继承为新实现验收|

HTTP载荷先作为`unknown`核验外壳、身份／对象、必要字段及原回执，再进入展示或状态更新。已知需要特别处理的推导差异在查询文档中按精确JSON路径列出；例如无Worker时的`worker.lastSeenAt`、缺平台设置时的`settings`，不能因为声明推为非空而直接解引用。部分操作错误的`details`也可携带`blockingOperation`，并非声明中的空值推断就能穷尽运行分支。

这不要求建立第二套DTO：保留公开类型，用公开schema及必要的信封／空值检查消费实际响应；出现不认识的错误或损坏回执时，保留未知，不伪造成功或释放占用。

## 4. 明确不能由前端补造的保证

- 管理员监管不授予买卖、直接撤单、编辑／启动／继续任务权限；任务控制仍可能推进早已配置的自动撤单授权，不能笼统称为纯只读。
- `tradingReady`、健康、连接成功、预检、SSE连接与真实成交不是同一事实。持仓候选、本地名义持仓和当次可卖库存不是同一个量。
- 并非所有写接口都有持久原回执；改密没有与原请求绑定的终态查询。登录成功、本地标记、相同输入、404、旧快照或等待时间不能伪造原请求终态。
- 任务停止／到期、订单终态、最终费用、库存核实与预留释放分别表达；FIXED尾量不足仍可能等待原窗口，不能由客户端宣布完成。
- 没有DELETE、忘记密码／管理员重置密码、独立本地全局成交分页、任意资源修改、任意文件／SQL读取、K线、虚拟资金、Testnet／Demo、自动划转换币、代签风险声明或完整官方盈亏计算能力。服务器JSONL运维日志经CLI管理，HTTP `/logs`仅提供授权业务事件。
- 原始需求要求评估买入任务的整份预计资金；当前启动按实际分支做单批或来源预检，未发现完整目标资金需求的公开评估。是否需要补齐该原始要求仍待确认，见[需求追溯](requirements-traceability.md)第十章。
- 迟到的失效会话响应可能影响新Cookie；[HTTP会话专题](http-and-events.md)区分隔离探针与项目全链路证据。前端忽略旧回调不能替代会话协议保障。
- 原操作输入归一化和无权读取的错误表达存在需处理的边界，见[写入与恢复](write-and-recovery.md)及[查询语义](query-and-response-contracts.md)；不能用前端提示替代后端授权和隐私保障。

能力限制按当前实现表达，不因重建客户端而自动变成新功能；未验证或尚未修复的问题不得标记为已解决。

## 5. 完备性核对与维护要求

接口目录、示例和独立类型消费的历史核对见[0062补全与清理记录](../changes/0062-complete-client-integration.md)。其中一次`contracts:check`字节校验失败的原因未定位，后续独立导出一致不等于已修复；验收要求也不等于新客户端已运行。

后续新增／删除路由、修改字段、动作、筛选、原ID、Cookie／错误／SSE时，同轮更新对应专题、接口目录和公开契约；按[接入验收文档](bootstrap-and-acceptance.md)最后一节的维护矩阵执行。历史记录不回填为新事实，本目录现状随真实实现维护。

本目录替代此前架构现状中零散的接入摘要，成为唯一完整的消费者阅读入口；架构和运维仍保留各自服务端职责。不要复制本目录为另一套“前端规格”，也不要从当前入口反复跳转旧实现资料。
