## 3. 结论摘要

只摘录结论，举证以报告正文的源码行号为准：

- **整体：有条件可行，不能原样冻结。** 后端已提供交易执行与管理前端所需的大部分能力；主要风险是契约不完整、三套状态与未知恢复混淆、资产真实性语义、异步缓存／会话竞态、UI 输入精度。
- **契约：** 52 个显式方法／路径均有声明入口；`client.d.ts` 是 Hono 客户端推导声明，不覆盖全部错误、流内错误、可空投影与原操作结果形状。Native Fetch 可用，需补辅助定义，不强制 Hono RPC／OpenAPI／workspace。
- **SSE：** 业务流是按库摘要轮询的资源提示，无补播、无游标，`operations` 等资源不在通知范围；行情流单证券连接、每用户每进程两类合计 6 条。必须以 REST 收敛，不能把提示当账本。
- **恢复：** 单笔下单走订单自身幂等，撤单等八类控制走持久回执，两条链路不得合并；任何情况下不得换标识重发未知订单或撤单。
- **安全：** 失效旧会话的 401 会按固定名删除 Cookie，源码路径已确认；旧响应晚于新登录删除新 Cookie 属推断，本轮未做浏览器复现。管理员的监管动作可能推进已授权的自动撤单，不是纯只读。
- **技术选型：** 保留 React／TypeScript／Vite／Router／Query／Table／RHF＋Zod／Fetch／EventSource／decimal.js／Intl；建议主 UI 由 Astryx 改为 MUI、默认删除 Tailwind、暂缓 Zustand／i18n 运行库／Sentry；IANA 时间编辑增加精确时间适配。
