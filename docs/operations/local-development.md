# 后端本地开发与运行

- 类型：开发指导；持续维护的现状说明。
- 版本：后端3.0.0，以`backend/package.json`为准。市价单与迁移0015见[0058](../changes/0058-market-orders.md)，历史后端部署见[0044](../changes/0044-nginx-production-redeploy-150.md)。
- 环境：Bun与已有PostgreSQL18.6；项目内依赖按后端锁文件安装，不安装全局工具。既往命令与结论按各原轮记录使用。
- 边界：Stocks 正式环境，动态支持官方证券含 ETF；买入需真实资金预检，卖出逐次核实官方Funding库存与证券身份；来源缺失或冲突时禁止卖出。

## 1. 后端项目与配置

后端`backend/`独立提供API／Worker，根目录没有应用依赖或统一运行入口。用户自行部署，不提供容器、反代或主机服务配置。历史证据按当前资料范围裁剪，仅保留原轮后端与业务功能证据；完整原文在Git历史。

后端 `.env.example` 为完整注释模板，私密 `.env` 不入库：

- `DATABASE_URL` 是唯一数据库连接。当前本机正式库是用户确认创建的 `equity_production`；旧 `equity_simulation`保留原用户和业务数据，不转换成正式资产或任务。
- `ENCRYPTION_KEY` 是 32 字节随机密钥的 64 个十六进制字符，API／Worker一致；不能随意更换，数据库备份需同时保管密钥。
- `BOOTSTRAP_*` 只初始化缺失管理员／交易员。密码至少16字符，已有账号不重置。首次初始化只创建缺失的网站账号，不创建交易账户、资金或任务；现有业务数据以实际数据库为准。
- 每位交易员的API Key／Secret经后端账户接口提交并在服务端加密，不在聊天／日志／文档输出凭据。
- `WORKER_INTERVAL_MS` 是每轮处理后的等待，不是下单间隔或订单超时。
- `BINANCE_BASE_URL` 为 `auto` 或白名单正式来源；通过 SDK只读测速选择，连接成功不等于资产及交易资格通过。
- `TRUSTED_PROXY_IPS` 默认空，精确列出可提供转发链的代理 IP；不默认信任回环。部署代理时必须配置其真实连接地址并追加正确的 XFF 链，避免按代理聚合来源限流或相信伪造头。

没有 `TRADING_ENV`、环境选择或本地撮合回退。

## 2. API、来源白名单与 Cookie

```dotenv
API_ORIGIN=http://127.0.0.1:3020
SESSION_COOKIE_SAME_SITE=strict
```

`HOST/PORT`控制后端监听，`API_ORIGIN`是客户端访问后端的对外来源；HTTPS反代部署时两者可能不同。`FRONTEND_ORIGINS`是后端保留的客户端来源白名单配置名，应按实际获准调用方设置。来源必须精确包含协议、主机和端口，不含业务路径、凭据或尾斜杠，不接受通配符，不自动放行其他端口。

HTTP与SSE访问API均须遵守凭据与来源策略。不同端口跨域但通常仍同站，本机统一用`127.0.0.1`；`localhost`与它不是同一主机。真正跨站Cookie的`none`仅搭配HTTPS，浏览器仍可能限制第三方Cookie。来源配置不能代替登录、CSRF、角色和所有权检查。

## 3. 初始化和开发

在后端目录执行：

```sh
bun install --frozen-lockfile
bun run setup
bun run dev
```

`setup` 以唯一连接的账号临时访问同实例 `/postgres`，创建明确指定但缺失的正式库，执行迁移及缺失平台账号初始化。缺库时需要建库权限；历史非正式标识或非空演示数据会被拒绝转换。用户历史库不因代码整理而修改或删除。

`dev`同时运行源码`src/server/index.ts`与`src/worker/index.ts`，不接测试网。API默认3020，公开元数据`/api/v1/meta`，健康`/healthz`；不存在的接口返回JSON错误。

已有`/healthz`允许精确`FRONTEND_ORIGINS`跨源读取，全部健康才200，Worker缺失、过期或DB异常为503；仅供获准调用方使用。API可达或事件连通不能代替健康判定，健康也不等于交易资格／资金就绪。

启动器、单独 API 和单独 Worker 均先核对数据库版本并自动执行缺失迁移，成功才记录 `DATABASE_READY`。`auto` 节点选择发生在此后；单独服务保留原有离线／冷却恢复能力，不新增强制公网探测。日志保留安全的 `service/stage/code/message/action`，补齐级别、真实耗时与来源；底层异常仅保留白名单代码、栈帧及原因，不回显SQL、响应正文或凭据。后端0.7.0的终端、文件和字段查询见[日志规范](backend-logging.md)。

客户端关闭不停止Worker；停止后端不会自动撤单或释放未知占用，重启先恢复核对。

## 4. 构建与分别运行

后端：

```sh
bun run build
bun run start
```

生成并运行 `dist/api.js`、`dist/worker.js`，运行时读取配置和凭据，不打包私密环境值。统一启动器通过官方SDK选择正式节点并传给两个进程；不接受交易环境选择参数。

分别启动源码用 `api:dev`／`worker:dev`，分别启动产物用 `api`／`worker`。API与Worker使用同一正式库和主密钥，不重复占用同一API端口。

## 5. 契约与源码结构

后端整体入口在`server`，应用用例与真实事务在`services`，纯金融规则在`domain`，SDK防腐层在`api`；其余配置／数据库／安全／校验／类型／工具／Worker分区。迁移位于`migrations`；设计理由及不引入的模式见[轻量DDD](../architecture/domain-driven-design.md)。

仅在公开接口变化时：

1. 后端运行 `bun run contracts:export`，从公开应用和schema导出两份规范快照；导出阶段使用已有TS7单线程选项，避免复杂Hono联合成员顺序抖动，仍完整类型检查。
2. 外部调用方按[独立接入资料](../integration/bootstrap-and-acceptance.md)同步公开契约，不依赖服务内部源码或SDK运行类型。
3. 后端公开源与实现的一致性检查现为 `contracts:source:check`；`contracts:prepare` 生成被忽略的 `backend/api-contracts/`，新的 `contracts:check` 只读检查该生成目录。前端以 `file:../backend/api-contracts` 安装，前端同名检查实际调用后端脚本并增加消费副本检查；完整重建工作流见[第三阶段 3-A](../changes/0071-frontend-readonly-business-features/0002-contract-migration-verification.md)。

新调用方从[完整接入资料](../integration/README.md)理解后端与实施客户端，覆盖全部接口、状态动作、查询行为、精确HTTP／SSE及原ID恢复。业务和权限以产品资料为准，字段使用当前公开契约；历史执行记录不能替代现行定义，原请求终态能力也不能由本地记录补造。

## 6. 验证与数据库迁移

后端`bun run check`运行格式、类型、隔离数据库测试、契约核对和构建；按改动范围选择最小充分验证。

后端的 `bun run test:db` 由 `scripts/test-db.ts` 创建本次专用 `equity_test_*` 临时库，只向测试子进程覆盖原来的 `DATABASE_URL`，执行后只删除自己创建的库；不在正式业务表跑回归，也不增加第二个连接配置项。测试账号需要维护库连接和建库权限，实际部署应用账号不必拥有这些权限。

定向回归可用 `bun run test:db tests/<用例文件>`，仍使用相同的临时建库、迁移及清理流程。不要直接把数据库回归指向正式库。

服务首次连接自动读取 `migrations/meta/_journal.json`、SQL及已执行哈希，持有同一保留连接的 advisory lock 完成“核对→迁移→复核”；API／Worker、多进程和同进程并发共用初始化门禁，重复连接会再次核对而不重复执行DDL。锁等待默认30秒；超时、较新数据库、哈希／日志不兼容、迁移失败、历史错库及资源缺失均阻断启动。结构版本来自迁移日志，不能用程序版本号或手填常量替代。

`db:generate` 仅用于开发追加迁移，历史 SQL 不重写；`db:migrate` 复用自动初始化实现，保留为可选的提前升级／诊断入口，不再是人工启动前置。需要升级时应用账号须有项目 DDL 权限；首次建库账号仍需建库权限，普通部署不必有服务器超级用户权限。空库结构升级不代表平台账号初始化，后者仍显式 `setup`／`db:seed`。

构建同时生成 `dist/api.js`、`dist/worker.js` 和完整 `dist/migrations`；迁移路径相对模块，不依赖当前工作目录。不得只部署两个JS或把资源缺失当作“数据库已经最新版”。不得直接修改历史成交或把旧资产置零／改名来消除差异。

## 7. 交易流程参考与实盘授权

以下为账户与交易接口对应的业务顺序，不构成实盘操作授权：

1. 交易员通过账户接口保存自己的Key／Secret，默认关闭交易。
2. 执行连接验证与资产同步，核对Funding USDC、Spot USDC、同步时间和错误。余额是官方读取快照，不是USD现金；空记录不伪造0。
3. 在币安官方确认账户／地区资格及免责声明，本系统不代签。交易员明确开启账户交易开关；方向准备度仍分别检查。
4. 证券代码由官方目录校验；任务保存与订单提交均校验当次有效规则。单笔、目标和固定数量使用十进制字符串，小数份额须符合官方规则。
5. 买入前读取真实Funding资金，覆盖本金、估算费用与本地待提交占用；预留政策由平台设置管理。预检不保证交易所接单或成交。
6. 已确认成交与官方实际费用入账；实际费用未提供时保持待核对。未知提交先查原客户订单，不再次创建或释放未知占用。

卖出与卖出任务按当次官方Funding可用余额和证券身份校验，来源缺失或冲突时禁止卖出；本地名义持仓不能代替官方库存。成交后库存比较只提供保守门禁，不证明原子同步，具体限制见[0042](../changes/0042-sell-production-integration.md)。全局能力可用不代表账户或当次订单一定可交易。

1.5.0新增0011／0012迁移，升级前停止旧API／Worker并备份数据库；启动新版本自动迁移后再恢复服务，不允许旧调度器与新版本同时运行。旧成交费用证据保守转待核对，不能批量解除`feePending`。56522fc已按此流程完成正式升级和只读验收，未真实买卖或撤单。自动撤单依赖Worker在线，停机或交易所不可达会延迟；GTC不因平台离线自动结束。官方200次／分钟／UID下单限制继续生效，小数秒配置不是持续吞吐保证。

账户存在未完成订单、尚未释放占用、已成交但最终费用或SELL库存待确认的订单，或未终结任务时，更换 Key／Secret 返回 `ACCOUNT_CREDENTIALS_IN_USE`。原值重复保存不会重置连接和资金快照，标签及安全管理仍可操作。系统不能证明两组不同凭据属于同一币安账户；旧凭据失效时也不能通过覆盖它跳过原订单核对。

订单`fee`表示已确认累计费用，`feeFinalized`才表示终态最终费用已经确认。终态响应不含费用时保留原累计值并继续核对；迟到费用只补记差额，不能把部分成交阶段费用当作最终值。

官方429／418、业务码-1003及Wallet频率码-4005均触发数据库共享冷却，覆盖API、Worker、账户和节点，不能换节点／重启绕过；即使HTTP不是429也处理相应业务包络。优先遵守可取得的`Retry-After`，缺失时从60秒退避（418为120秒），连续失败指数递增至15分钟；官方指定的更长等待不截短。真实限流不等于未发送，不重发未知订单或释放占用；逐码和按操作恢复见[错误审计](../reference/stocks-error-handling.md)。

### 2.0.0 配套升级

账户检查、资产同步、主动核对三个POST现在要求UUID`Idempotency-Key`，返回原回执；旧客户端不能混用。部署仍需单独授权，升级时停止旧写服务、备份数据库及主密钥，并配套更新调用方、API与Worker。本次复用0009回执表，不新增SQL迁移，也不补造历史原请求。

CHECK/SYNC在账户结果与原回执同事务落库后结束；GET仅在执行锁／事务锁证据成立时证明原结果未应用。ACCOUNT_RECONCILE冻结原对象范围，只有原操作者可通过`POST /operations/:id/reconcile`继续原核对，不提交或撤销新交易。其他有权查看者仍可GET原回执；不同账户的保护相互独立。

同步失败状态可能已经写入：HTTP错误携带成功原回执时，不可重发已应用操作，也不能把它称为资金同步成功。当前账户快照、404、删除客户端记录或等待固定时长不能解锁。回滚保留未终结回执并停止相关写入，不让旧服务绕过；详见[账户回执契约](../architecture/account-operation-receipts.md)。

### 旧版升级

停止旧API／Worker并备份正式库和原加密主密钥，再配套升级调用方与服务至1.0.0协议。五类高风险写入新增必需UUID原操作标识和原回执，旧客户端不能混用；首次连接追加0009回执表，不回填历史伪终态，也不改金额／订单。保留原`DATABASE_URL`、完整迁移资源和业务数据，不将历史模拟库转换为正式资产。本轮仅在自建临时库验证，没有部署或迁移正式库。

0005–0007的精确数量／方向／资金版本约束和0008的共享冷却及 `orders.fee_finalized` 均保留原历史金额、窗口与审计。历史订单最终费用默认待核对，可能暂时阻止新增买入或换凭据；不能批量标记已确认来绕过。0011是当时执行事实，本轮自动迁移、并发、失败回滚与独立产物运行证据见[0013](../changes/0013-startup-domain-stocks-errors.md)；本轮只在自建临时库执行升级回归，不主动迁移正式业务库。

若本地冷却门禁在下单HTTP发送前明确阻断，本地意图安全终结并释放其预留，事件标注 `LOCAL_ABORTED` 和未发送证据。真实429、网络未知或提交后的观察冷却均不属于该情况，仍保留原订单核对。

原操作GET只核对持久回执及执行证据，不调用交易所或重放写入；可据此推进回执本身，但不把当前对象旧快照当终态。主动原ID业务核对使用专用POST，不能变成原动作重试。未知记录无固定到期释放；回滚必须停止相关写入并保留回执，不能删表或让旧API绕过。认证前未登记／404、损坏存储或主体不符仍需核实，见[操作契约](../verification/operation-contract-review.md)。

任务计划维持UTC Z及完整更新：未编辑／精确等价保留原JSON和原列，创建／真实改时超过6位有效小数明确422，已开始任务真实改时仍409；顶层Date DTO不能重建微秒配置。没有批量规范化历史任务，详见[时间契约](../verification/task-time-contract-review.md)。

私有流失败与一次性事件分开：无效listenKey、权限或订阅失败关闭旧资源，原30秒退避期间Worker持续降级，成功重建或移除账户才恢复；重复周期不刷同一错误日志。正常停止先发SIGTERM，启动器从首次请求停止起计30秒，超时强制停止剩余子进程；这不是撤销订单，未知意图仍须恢复核对。
